# Information Hierarchy

Arrange a note so a reader can understand the point without digging through setup first. Start where the reader needs to start: the problem, a concrete incident, the decision, or the mechanism.

Use headings to make the argument easy to scan. Add context, examples, operational detail, and a conclusion only when they clarify the subject. A short note may need none of those as separate sections.

When revising an existing note, inspect its outline and move material only when the current order hides an important dependency or conclusion. Preserve useful evidence and technical detail; do not force every idea into a prescribed sequence.
