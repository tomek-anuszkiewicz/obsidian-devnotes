# Language-Agnostic Architecture

Use this skill when the lesson should apply beyond one framework or language. Explain the durable part first: who owns state, where data moves, what starts a transaction, how failure is handled, or what limits throughput.

Use a concrete language, framework, or tool when it makes the mechanism clearer or when the note is specifically about that technology. Do not replace useful code with pseudocode merely to look general, and do not add examples from multiple ecosystems just to balance a list.

Choose diagrams, pseudocode, measurements, or source examples for the job they do. The reader should leave knowing what happens in a real system and which details are implementation-specific.
